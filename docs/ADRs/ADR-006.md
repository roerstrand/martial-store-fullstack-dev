# ADR-006: Klient på Vercel, API på Render via rewrite

- **Status:** Accepterad
- **Beslutsdatum:** 2026-06-07
- **Dokumenterad:** 2026-11-15 (i efterhand, se [README](README.md))
- **Underlag i historiken:** `68be0a5` (Vercel-konfiguration för routing), `client/vercel.json`, `client/src/services/apiBaseUrl.js`

## Kontext

Shoppen ska vara publikt tillgänglig. Klienten är statiska filer från `vite build`, och servern är en Express-process som behöver köras hela tiden och nå MongoDB. React Router kräver att alla sökvägar serverar `index.html`.

## Alternativ

**A. Vercel för klienten, Render för API:t och en rewrite av `/api` från Vercel till Render (valt)**
- Fördelar: gratisnivåer för båda, varje del driftsätts oberoende, och klienten anropar `/api` på sin egen domän, så webbläsaren ser samma ursprung.
- Nackdelar: två plattformar att konfigurera, och Renders gratisnivå har kallstart efter inaktivitet.

**B. Allt på Render, där Express även serverar klientens build**
- Fördelar: en tjänst och ett ursprung.
- Nackdelar: klient och server driftsätts alltid tillsammans, och statiska filer serveras utan CDN.

**C. En VPS med Nginx och PM2**
- Fördelar: full kontroll.
- Nackdelar: drift, säkerhetsuppdateringar och certifikat måste skötas manuellt.

## Beslut

Alternativ A. `client/vercel.json` skickar `/api/*` vidare till Render och alla andra sökvägar till `index.html`. `services/apiBaseUrl.js` använder `/api` i produktion och `VITE_API_URL` eller Vites proxy under utveckling.

## Konsekvenser

- Klienten kan driftsättas om utan att API:t påverkas, och tvärtom.
- Cookie-inställningarna i ADR-004 är anpassade för att fungera även utan rewrite.
- Första anropet efter en tids inaktivitet kan ta flera sekunder.
