# ADR-001: Monorepo med React/Vite-klient och Express-server

- **Status:** Accepterad
- **Beslutsdatum:** 2026-04-29
- **Dokumenterad:** 2026-11-15 (i efterhand, se [README](README.md))
- **Underlag i historiken:** `6bf2e25` (initial projektstruktur), `e60027e` (server och konfiguration), `2c075ef` (concurrently för att starta båda delarna)

## Kontext

Webbshoppen behöver ett gränssnitt för kunder och admin samt ett API med databas. Både klient och server skrivs i JavaScript och utvecklas parallellt av samma person. Kravspecifikationen kräver en fullstack-lösning med separat frontend och backend.

## Alternativ

**A. Ett repo med två separata projekt, `client/` och `server/` (valt)**
- Fördelar: en historik för hela lösningen, enkelt att ändra API och klient i samma commit, var del har egna beroenden och kan driftsättas separat.
- Nackdelar: två `package.json` och två `node_modules`, och rotskript behövs för att starta båda.

**B. Två separata repon**
- Fördelar: fullständigt oberoende versionering och driftsättning.
- Nackdelar: ändringar som spänner över API och klient blir två commits i två repon, och det är svårare att hålla dem i synk.

**C. Ett ramverk för både klient och server (t.ex. Next.js)**
- Fördelar: en server, inbyggd routing och rendering på servern.
- Nackdelar: Express och ett separat REST-API var en del av kursens mål, och ramverket döljer lagerindelningen i servern.

## Beslut

Alternativ A: ett repo med `client/` (React och Vite) och `server/` (Express). `concurrently` i rotens `package.json` startar båda med `npm run dev`.

## Konsekvenser

- Klient och server kan driftsättas på olika plattformar (se ADR-006).
- Under utveckling går API-anropen via Vites proxy (`/api` till `localhost:3000`), och CORS är konfigurerat för produktion.
- Rotens `npm test` kör båda testsviterna.
